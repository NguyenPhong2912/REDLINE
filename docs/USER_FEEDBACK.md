# REDLINE user-feedback protocol

## Goal

Validate whether treasury operators and agent developers understand the permission boundary, trust the risk-review flow, and value the on-chain proof enough to adopt a pilot.

## Test flow

1. Open the production demo.
2. Say which numbers on screen you would trust, and what would make you doubt one.
3. Build one low-risk policy and one intentionally dangerous policy.
4. Compare the ALLOW/REVIEW/BLOCK verdicts.
5. If a Devnet wallet is available, publish a Memo proof and inspect it in Explorer.

## Interview questions

1. In your own words, what does REDLINE protect?
2. Which policy limit mattered most to you, and which was confusing?
3. Did the deterministic/AI source label change your trust in the verdict?
4. What would stop you from connecting a treasury wallet?
5. Which integration is required before you would run a pilot?
6. Would you pay for policies, approvals, alerts, or audit exports? Why?

## Evidence rule

Do not fabricate responses or count internal team opinions as external validation. Record the participant role, test date, top problem, trust concern, requested feature, and willingness to pilot. Never collect seed phrases, private keys, API keys, wallet balances, or personally identifiable financial data.
